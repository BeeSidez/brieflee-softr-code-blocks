- **Bot walls now trigger a stealth-proxy retry, in both engines** (`ad04c053` version `1de8bf30`, `70a72dc3` version `1617b99e`; verified identical in both live sources, no unused declarations, every new symbol defined and referenced).
- **Why Firecrawl's own `proxy: "auto"` would NOT have fixed this.** Auto only retries when the basic attempt FAILS. A Cloudflare challenge answers with **HTTP 200** and a near-empty page, so it reads as a successful scrape and auto never fires. `esmeconsumer.in` returns exactly that: 403 to a plain fetch, and to Firecrawl a 200 carrying "Just a moment... Enable JavaScript and cookies to continue". That is why Nature's Essence stored a 0-char `website_scrape` and the model produced a placeholder bio. The retry has to be driven from our side.
- **The shape:** `scrape()` split into `scrapeOnce(target, proxyMode)` plus a `looksBlocked()` gate. Pass one runs Firecrawl's default. If the result is missing, under `MIN_USEFUL_SCRAPE` (400 chars) or matches `BOT_WALL`, pass two runs with `proxy: "stealth"` and the better of the two results is kept, so a stealth attempt can never make things worse. `STEALTH_TIMEOUT_MS` is 60s against the basic 30s, which keeps a single url's worst case at 90s, under the Softr proxy's ~120s ceiling.
- **Cost is bounded on purpose:** stealth routes through mobile proxies and bills 4 extra Firecrawl credits per successful scrape, so it only ever runs as a second pass, never by default.
- **The detector was tested against real data before being called done**, running the exact pushed predicate under node: the real 58-char Esme challenge → retry, empty and null → retry, a real 60,000-char Amazon product scrape → keep (no false positive), a 433-char brand description → keep, Cloudflare wording inside a longer page → retry.
